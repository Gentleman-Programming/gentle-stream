# gentle-stream

Real-time generative lo-fi in your terminal. Tell it a feeling, a concept or a place; Gentle Shell turns it into
musical parameters and the music changes at the next bar, without stopping.

The sound comes from the same procedural synthesis used for the Gentleman Programming YouTube videos
(`lofi_mel.py`): felt piano, rhodes, nylon guitar and pads over minor/modal progressions, sub bass, dusty swung
drums, vinyl crackle, a small room and tape wow. Here it is rendered bar by bar while it plays, so it never ends
and never repeats exactly.

The TUI uses the gentlemanprogramming.com palette (a `gentleman` Textual theme): rose and pink on deep plum.

## Requirements

- [uv](https://docs.astral.sh/uv/)
- [Gentle Shell](https://github.com/Gentleman-Programming/gentle-pi) (`gentle-shell` on your `PATH`) with at least
  one signed-in model provider
- An audio output device

## Run

```sh
uv run gentle-stream                       # starts playing right away
uv run gentle-stream --mood "rainy night in a small café"
uv run gentle-stream --model claude-bridge/claude-haiku-5-5
uv tool install .                          # then just: gentle-stream
```

| Flag | Meaning |
|------|---------|
| `--model provider/id` | Model Gentle Shell uses to interpret moods (default: Gentle Shell's default). |
| `--mood TEXT` | Mood to interpret as soon as the app starts. |
| `--gentle-shell PATH` | `gentle-shell` executable to run (default: `gentle-shell`). |

## Sampled instruments (optional)

By default every instrument is synthesized. For sampled piano, rhodes, nylon guitar, pad and drums, install
FluidSynth and the FluidR3_GM soundfont once:

```sh
brew install fluid-synth                   # or your system's fluidsynth package
uv run gentle-stream setup-samples         # downloads ~120 MB once; nothing is downloaded otherwise
```

`setup-samples` downloads Debian's `fluid-soundfont-gm` package
(`https://deb.debian.org/debian/pool/main/f/fluid-soundfont/fluid-soundfont-gm_3.1-5.3_all.deb`), checks it
against a pinned SHA-256, extracts `FluidR3_GM.sf2` into `~/.cache/gentle-stream/` (or `$XDG_CACHE_HOME`) and
writes `LICENSES.txt` next to it with the source, checksum and license. Running it again does nothing.

FluidR3_GM is MIT licensed (Copyright © 2000-2002, 2008 Frank Wen; © 2008 Toby Smithe), so music made with it can
be used commercially; keep the MIT notice from `LICENSES.txt`. The soundfont is never committed to or shipped with
this repository. The reverb uses an impulse response generated by gentle-stream's own code, not a recording.

The Python binding is `pyfluidsynth` (installed by `uv run`; for `uv tool install`, use `uv tool install
'.[samples]'`). If the soundfont, FluidSynth or the binding is missing, gentle-stream keeps the procedural
instruments. The sub bass stays synthesized either way, and the genre's master chain applies to both.

## Controls

| Key | Action |
|-----|--------|
| `space` | Play / pause (smooth fade, no clicks) |
| `n` | Next piece with the same mood: new key, progression, melody and groove |
| `/` | Describe a mood, `Enter` to send, `Esc` to leave the input |
| `m` | Choose the model Gentle Shell uses (listed from `gentle-shell -- --list-models`) |
| `s` | Save what is playing under a name (`Enter` saves, `Esc` cancels) |
| `p` | Saved prompts: `Enter` applies one instantly, `d` / `Delete` removes it, `Esc` closes |
| `+` / `-` | Volume up / down by 5% |
| `↑` / `↓` | Volume up / down by 1% |
| `q` | Quit |

## Token usage

Only describing a mood calls a model. After each interpretation the status line shows what that call used
(`Up next: … · 17.7k tokens · $0.0001`), and the model line keeps a running total for the session
(`model: … · session: 35.4k tokens · $0.0015`). The cost is the one Gentle Shell reports in US dollars; providers
used through a subscription (such as `claude-bridge`) report `$0.0000`. Failed or cancelled requests add nothing.
Playback, `n`, pause, volume and saved prompts never call a model, so they cost no tokens.

## Saved prompts

Liked what a mood turned into? Press `s` and give it a name. gentle-stream saves the prompt together with the
musical parameters it produced (key, mode, tempo, progression, instruments, colour). Press `p` later to apply it:
it starts at the next bar, sounds like it did when you saved it and needs no model call. Every piece is still
newly generated.

Saved prompts live in `~/.config/gentle-stream/presets.json` (or `$XDG_CONFIG_HOME/gentle-stream/presets.json`).
The file is plain JSON, rewritten atomically. If it becomes unreadable, the app says so and leaves it untouched;
invalid entries are skipped and every value is validated like a model answer.

## Genres

Lo-fi is the default. The model picks a genre from your mood, or you can name one (`"jazz for a rainy night"`):
`lofi`, `ambient`, `chiptune`, `synthwave`, `jazz` and `rock` (rock covers metal: busy drums at high energy).
The genre is part of the style, so it shows on the details line, survives `n` and is kept by saved prompts
(prompts saved before genres existed load as lo-fi). Every genre keeps the same song form and only plays
originally composed material; the model is told never to reproduce existing melodies.

Each genre is one module in `src/gentle_stream/genres/` (`base.py` documents the interface): its voices
(procedural or FluidR3_GM programs and drum kits), rhythmic treatment, drum patterns and master-chain settings.
Today only `lofi` is implemented; the other five are placeholders that play the lo-fi sound.
`tests/test_genres_contract.py` checks every registered genre on both backends.

## How it works

- **Genres** (`genres/`): a registry of genre plugins; for each bar the style's genre turns the composer's plan
  into notes and sets the master chain. Shared oscillators, envelopes and a waveshaper live in `synth.py`.
- **Engine** (`engine.py`): schedules each bar's notes into a buffer where their tails ring into later bars, then
  passes the finished bar through a master chain (vinyl, room, convolution reverb, tape wow, tone, bus
  compressor, tape saturation) whose filters, delay lines, reverb tail and compressor envelope keep their state,
  so bars join seamlessly; a genre's different master settings glide in over the first bar. It renders about 40 times faster than real time with the procedural instruments and
  over 100 times with samples (rendered notes are cached).
- **Samples** (`samples.py`): downloads and verifies FluidR3_GM, and renders single notes offline with FluidSynth
  into the same interface as the procedural instruments, level-matched to them.
- **Mastering** (`mastering.py`): a procedurally generated stereo impulse response (1.5-2.5 s, longer with more
  `space`) applied by overlap-add FFT convolution, an RMS bus compressor with attack/release, and a soft clip.
- **Player** (`player.py`): a producer thread keeps about one second of audio ahead; the audio callback only
  copies samples. `next` renders the new piece's first bar immediately and crossfades it over the old one.
  The screen shows the bar you are hearing, not the one being rendered.
- **Mood interpretation** (`bridge.py`): runs
  `gentle-shell -- -p --mode json --no-session -nt -ns -np -nc --no-mcp --no-themes --no-skill-registry
  --thinking off [--model …] "<prompt>"`, reads the answer text and token usage from the final assistant
  `message_end` event (plain-text output from older Gentle Shell versions still works, without usage) and expects
  one JSON object with `name`, `genre`, `key`, `mode`, `bpm`, `progression`,
  `chords`, `lead`, `drums`, `energy`, `brightness`, `swing`, `vinyl`, `space` and `lead_density`. Every value is
  validated and clamped; anything missing keeps the current style. Extensions stay enabled because some model
  providers (such as `claude-bridge`) are extensions. A request takes a few seconds; the music keeps playing
  meanwhile, and a failure is shown in the status line without touching the music.
